# Contributing

This repository is a personal learning project focused on Python for engineering, automation, robotics, and embedded systems.

Although it is primarily a personal portfolio, these guidelines define how exercises, notes, and projects should be organized and maintained.

---

# Coding Standards

- Write clean, readable code.
- Use meaningful variable and function names.
- Follow PEP 8 where practical.
- Use consistent indentation and spacing.
- Add comments only when they improve understanding.
- Prefer clarity over cleverness.
- Use descriptive program output for engineering simulations.
- Test each exercise before committing it.

---

# File Naming

## Exercises

Use numbered, descriptive filenames:

```text
01_count_to_10.py
02_even_numbers.py
03_countdown.py
```

## Mini Projects

Use descriptive snake_case filenames:

```text
engineering_calculator.py
engineering_safety_monitor.py
automated_machine_inspection_simulator.py
```

## Documentation

Use clear Markdown filenames:

```text
README.md
ROADMAP.md
CHANGELOG.md
notes.md
```

---

# Learning Structure

Each topic should include:

- `README.md`
- Practice exercises
- Personal notes
- Engineering-focused examples
- A mini-project when appropriate

Example:

```text
03_loops/
├── README.md
├── 01_count_to_10.py
├── 02_even_numbers.py
├── 03_countdown.py
└── notes.md
```

---

# Learning Approach

For each topic:

1. Learn the core concept.
2. Complete progressively harder exercises.
3. Connect the concept to engineering applications.
4. Build a mini-project.
5. Update the documentation and changelog.
6. Commit the completed work to GitHub.

---

# Project Goals

The focus of this repository is to:

- Learn Python fundamentals.
- Build engineering applications.
- Develop automation tools.
- Prepare for embedded software development.
- Interface Python with STM32 microcontrollers.
- Create a professional engineering portfolio.

---

# Version Control

- Commit changes regularly.
- Write clear, meaningful commit messages.
- Keep commits focused on one logical change.
- Keep the repository organized and documented.
- Update `CHANGELOG.md` after completing a topic or project.

Example commit messages:

```text
Complete loop exercises
Add automated machine inspection simulator
Update roadmap after completing loops
```
